# 画面設計（レイアウト・画面項目定義・画面イベント）

> 機能設計書の一部。**画面一覧・ルート・対応コンポーネント・画面遷移の正本**は
> [`functional-design.md`](../../../baseline/functional-design.md)「画面設計」。本ファイルは各画面の
> **レイアウト（ワイヤーフレーム）・画面項目定義・画面イベント・画面状態**の詳細のみを置く。
> - UI 表示仕様（色・状態表現・ヒートマップの配色）は [`cross-cutting.md`](../../_shared/cross-cutting.md)「UI設計」を正本とする。
> - 各 API の入出力は [`api-design.md`](./api-design.md)、データ型は baseline の「データモデル」を参照。
> - 入力バリデーションの規則（繰り返しルール整合）は baseline「データモデル」の整合表と FR-06 を正本とし、
>   本ファイルは画面上の見せ方（どの項目をいつ出す/必須にする）に徹する（規則そのものを再定義しない）。
> 第一マイルストーン（単一ユーザー前提、認証なし）の4画面を対象とする。

## 共通事項

### 画面共通の状態表現

各画面はデータ取得を伴うため、以下の状態を持つ（表示仕様の詳細は `cross-cutting.md`「UI設計」）。

| 状態 | 表示 |
|---|---|
| ローディング | スケルトン／スピナー |
| エラー | エラーメッセージ＋再試行導線（メッセージは `cross-cutting.md`「エラーハンドリング」に対応） |
| 空（データ0件） | 空状態メッセージ＋主要アクションへの導線（例: 「習慣を登録しましょう」） |
| 正常 | 各画面の本体 |

### 凡例（画面項目定義の列）

- **項目**: 画面上の要素名／入力フィールド名
- **種別**: 表示（read）／入力（テキスト・数値・選択・トグル・日付 等）
- **必須**: 入力項目における必須/任意（表示項目は「—」）
- **初期値／取得元**: 既定値、または表示値の取得元 API
- **入力チェック／備考**: 画面上の制約・表示条件（規則の正本は baseline / FR-06）

## 画面1: ダッシュボード（`/` / `DashboardPage`）

当日の対象習慣とサマリーを一望する。関連機能: FR-07, FR-08, FR-10, FR-12, FR-14, FR-15, FR-16。

### レイアウト（ワイヤーフレーム）

```
┌───────────────────────────────────────────────────────────┐
│ HabitOS                          [習慣管理] [日付を選んで記録] │  ← ヘッダ/ナビ
├───────────────────────────────────────────────────────────┤
│ 2026-07-25 (土) の習慣                                       │
│ ┌───────────────────────────────────────────────────────┐ │
│ │ ☐ ランニング        運動    🔥 5日   [⚠ 07:00 超過]     │ │  ← 当日対象＋超過ハイライト
│ │ ☑ 読書              学習    🔥 12日                      │ │
│ │ ☐ ストレッチ        健康    🔥 0日                       │ │
│ └───────────────────────────────────────────────────────┘ │
│                                                             │
│ ┌─ サマリー ──────────────┐  ┌─ ヒートマップ ────────────┐ │
│ │ 今週の達成率  ◐ 75%      │  │ [カレンダーグリッド 直近数週] │ │
│ │ 今月の達成率  ◐ 68%      │  │ ■□■·■  ·:非対象 □:未 ■:完了 │ │
│ └─────────────────────────┘  └───────────────────────────┘ │
└───────────────────────────────────────────────────────────┘
```

### 画面項目定義

| 項目 | 種別 | 必須 | 初期値／取得元 | 入力チェック／備考 |
|---|---|:--:|---|---|
| 日付見出し | 表示 | — | 当日（サーバーローカル日付） | 当日のみ。過去日記録は「日付指定チェックイン」画面へ |
| 当日対象習慣リスト | 表示 | — | `GET /check-ins?date=today`（API-06） | その日が対象の習慣のみ（対象日判定は baseline アルゴリズム） |
| 完了チェックボックス | トグル | — | 各習慣の `status`（done=✓ / それ以外=☐） | 変更で API-07 を呼ぶ。楽観更新（`cross-cutting.md` 参照） |
| カテゴリ表示 | 表示 | — | `habit.category` | 未設定なら非表示 |
| 現在ストリーク | 表示 | — | `GET /dashboard`（API-08）の `currentStreak` | 「🔥 N日」バッジ（`weekly_count` は「N週」） |
| リマインド超過ハイライト | 表示 | — | API-06 の `overdue` | 当日の対象かつ未完了かつ `reminderTime` 超過のみ警告色（FR-10） |
| 週次/月次 達成率 | 表示 | — | API-08 の `achievementRate` | リング＋%。対象日0なら「対象なし」（率非表示） |
| ヒートマップ | 表示 | — | API-08 の `heatmap[]` | 配色は `cross-cutting.md`「カラーコーディング」 |

### 画面イベント

| 操作 | アクション | 結果 |
|---|---|---|
| チェックボックスを切り替え | `PUT /habits/{id}/check-ins/{today}`（API-07） | 楽観更新で即時反映→ストリーク/達成率を再取得（API-08） |
| 「習慣管理」クリック | 遷移 | `/habits`（HabitsPage） |
| 「日付を選んで記録」クリック | 遷移 | `/check-ins?date=...`（CheckInPage） |
| 習慣名クリック | 遷移 | `/habits/{id}`（HabitDetailPage） |

## 画面2: 習慣管理（`/habits` / `HabitsPage`）

習慣の一覧・作成・編集・アーカイブ。関連機能: FR-01〜FR-06。

### レイアウト（ワイヤーフレーム）

```
┌───────────────────────────────────────────────────────────┐
│ 習慣管理                                    [＋ 新しい習慣]    │
├───────────────────────────────────────────────────────────┤
│ ┌───────────────────────────────────────────────────────┐ │
│ │ ランニング   運動   月・水・金        07:00  [編集][削除] │ │  ← 習慣一覧（archived=false）
│ │ 読書         学習   毎日              22:00  [編集][削除] │ │
│ │ 筋トレ       健康   週3回             —      [編集][削除] │ │
│ └───────────────────────────────────────────────────────┘ │
│                                                             │
│ ┌─ 習慣フォーム（新規/編集：モーダル or インライン）─────────┐ │
│ │ 習慣名     [___________________]                        │ │
│ │ カテゴリ   [___________________]（任意）                 │ │
│ │ 繰り返し   ( ) 毎日  ( ) 週N回  (•) 特定曜日             │ │
│ │   └ 週N回 → 回数 [ 3 ] /週                               │ │
│ │   └ 特定曜日 → [日][月][火][水][木][金][土]（複数選択）   │ │
│ │ リマインド [ 07:00 ]（任意）                             │ │
│ │                                   [キャンセル] [保存]    │ │
│ └───────────────────────────────────────────────────────┘ │
└───────────────────────────────────────────────────────────┘
```

### 画面項目定義（習慣フォーム）

| 項目 | 種別 | 必須 | 初期値／取得元 | 入力チェック／備考 |
|---|---|:--:|---|---|
| 習慣名 | 入力（テキスト） | 必須 | 空（編集時は既存値） | 1〜100文字（baseline `habits_name_len`） |
| カテゴリ | 入力（テキスト） | 任意 | 空 | 100文字以内 |
| 繰り返し種別 | 入力（ラジオ） | 必須 | `daily` | `daily` / `weekly_count` / `specific_days`（`RecurrenceType`） |
| 週間目標回数 | 入力（数値） | 条件付き必須 | 空 | **種別=`weekly_count` のときのみ表示・必須**。1〜7（FR-06） |
| 対象曜日 | 入力（複数選択） | 条件付き必須 | 空 | **種別=`specific_days` のときのみ表示・必須**。1つ以上（0=日〜6=土） |
| リマインド時刻 | 入力（時刻） | 任意 | 空 | `HH:MM`。保持のみ（実配信なし、FR-05） |

> 種別に応じた項目の出し分け・必須切り替えが本画面の要。整合規則の正本は baseline「データモデル」の
> 繰り返しルール整合表と FR-06。画面は「種別を選ぶと該当項目だけ現れ、他は隠れる」挙動で規則を体現する。

### 画面項目定義（習慣一覧）

| 項目 | 種別 | 取得元 | 備考 |
|---|---|---|---|
| 習慣名／カテゴリ | 表示 | `GET /habits`（API-01） | `archived=false` のみ |
| 繰り返しルール要約 | 表示 | 同上 | 「毎日」「週3回」「月・水・金」等に整形して表示 |
| リマインド時刻 | 表示 | 同上 | 未設定は「—」 |
| 編集／削除ボタン | 操作 | — | 下記イベント参照 |

### 画面イベント

| 操作 | アクション | 結果 |
|---|---|---|
| 「＋ 新しい習慣」 | フォームを新規モードで開く | 空フォーム表示 |
| 「編集」 | フォームを編集モードで開く（`GET /habits/{id}` API-03 または一覧の値） | 既存値を投入 |
| フォーム「保存」（新規） | `POST /habits`（API-02） | 成功で一覧に追加。400 はフィールド単位のエラー表示 |
| フォーム「保存」（編集） | `PUT /habits/{id}`（API-04） | 成功で一覧更新 |
| 「削除」 | 確認後 `DELETE /habits/{id}`（API-05） | 論理削除（`archived=true`）。一覧から除外 |
| 習慣名クリック | 遷移 | `/habits/{id}`（HabitDetailPage） |

## 画面3: 日付指定チェックイン（`/check-ins?date=YYYY-MM-DD` / `CheckInPage`）

過去日を選んで対象習慣を記録・修正する。関連機能: FR-07, FR-08, FR-09。

### レイアウト（ワイヤーフレーム）

```
┌───────────────────────────────────────────────────────────┐
│ 日付を選んで記録         日付 [ 2026-07-20 ▼ ]   [← 戻る]   │
├───────────────────────────────────────────────────────────┤
│ 2026-07-20 (月) が対象の習慣                                 │
│ ┌───────────────────────────────────────────────────────┐ │
│ │ ランニング   運動    ( 完了 | 未完了 )                   │ │  ← トグル
│ │ 読書         学習    ( 完了 | 未完了 )                   │ │
│ └───────────────────────────────────────────────────────┘ │
│ ※ この日が対象でない習慣は表示されません                     │
└───────────────────────────────────────────────────────────┘
```

### 画面項目定義

| 項目 | 種別 | 必須 | 初期値／取得元 | 入力チェック／備考 |
|---|---|:--:|---|---|
| 日付ピッカー | 入力（日付） | 必須 | URL クエリ `date`、無ければ当日 | `YYYY-MM-DD`。未来日の扱いは当面「選択可・記録可」（対象日なら） |
| 対象習慣リスト | 表示 | — | `GET /check-ins?date=`（API-06） | 選択日が対象の習慣のみ（非対象は非表示） |
| 完了／未完了トグル | 入力（トグル） | 任意 | 各習慣の `status`（未記録は未選択） | 変更で API-07。非対象日への記録はそもそも項目が出ない＝422 を UI で予防 |

### 画面イベント

| 操作 | アクション | 結果 |
|---|---|---|
| 日付を変更 | URL クエリ更新→`GET /check-ins?date=`（API-06）再取得 | 対象習慣リストを差し替え |
| トグルを操作 | `PUT /habits/{id}/check-ins/{date}`（API-07） | 記録・修正を反映（FR-09）。ストリーク/達成率は次回参照時に再計算 |
| 「戻る」 | 遷移 | `/`（DashboardPage） |

## 画面4: 習慣詳細（`/habits/{id}` / `HabitDetailPage`）

個別習慣の継続推移を確認する。関連機能: FR-12, FR-14, FR-15。

### レイアウト（ワイヤーフレーム）

```
┌───────────────────────────────────────────────────────────┐
│ ← 習慣一覧   ランニング（運動 / 月・水・金）      [編集]      │
├───────────────────────────────────────────────────────────┤
│ ┌─ 現在 ──┐ ┌─ 最長 ──┐ ┌─ 達成率 ──┐                      │
│ │ 🔥 5日   │ │ 🏆 21日 │ │  ◐ 75%    │                      │
│ └─────────┘ └─────────┘ └───────────┘                      │
│ ┌─ ヒートマップ（対象日/完了/未達成/未記録を色分け）────────┐ │
│ │ [月次カレンダーグリッド]                                  │ │
│ └───────────────────────────────────────────────────────┘ │
└───────────────────────────────────────────────────────────┘
```

### 画面項目定義

| 項目 | 種別 | 取得元 | 備考 |
|---|---|---|---|
| 習慣ヘッダ（名前/カテゴリ/ルール） | 表示 | `GET /habits/{id}`（API-03） | ルールは要約表示 |
| 現在ストリーク | 表示 | `GET /dashboard`（API-08）の該当習慣 `currentStreak` | 「🔥 N日」（`weekly_count` は「N週」） |
| 最長ストリーク | 表示 | 同上 `longestStreak` | 「🏆 N日」 |
| 達成率 | 表示 | 同上 `achievementRate` | リング＋%。対象日0なら「対象なし」 |
| ヒートマップ | 表示 | 同上 `heatmap[]` | 配色は `cross-cutting.md`「カラーコーディング」 |

### 画面イベント

| 操作 | アクション | 結果 |
|---|---|---|
| 「編集」 | 遷移（または編集フォームを開く） | `/habits`（HabitsPage）で当該習慣を編集 |
| 「← 習慣一覧」 | 遷移 | `/habits`（HabitsPage） |

## 詳細設計への申し送り

- 具体的なコンポーネント分割・props 設計・状態管理（TanStack Query のキー設計等）は詳細設計／実装
  （`.steering/` と frontend リポジトリ）で確定する。本書は外部設計（画面の見た目・項目・イベント）に留める。
- モーダル/インラインフォームの採用、日付ピッカーの UI ライブラリ選定は実装時に決める。
- 画面を追加・変更したら、baseline「画面設計」の画面一覧・遷移図を先に更新し、本書を追随させる。
