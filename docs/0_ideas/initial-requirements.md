## 解決したい課題

- **主目的**: ウォーターフォール型の開発ワークフロー（要件定義→基本設計→詳細設計→テスト設計
  →実装→結合テスト）を一通り回すこと。HabitOS はその題材。
- プロダクトとしては、日々の習慣を登録・チェックインし、ストリークと達成率で継続を可視化する
  Web アプリ「HabitOS」。習慣継続のモチベーション維持を支援する。
- 題材としての適性: ドメインモデルが明確で非自明なロジック（繰り返しルール／ストリーク計算／
  集計）を持ち、設計・テスト設計が映える。フロント↔バックの連携があり結合テストの題材になる。

## ターゲットユーザー

- 第一マイルストーンは**単一ユーザー前提**（認証・マルチユーザーなし）。
- 開発者自身が日々使える実用性も兼ねる。

## 主要機能

1. **習慣の管理（CRUD）** — 名前・カテゴリ・繰り返しルール（毎日／週N回／特定曜日）で登録・
   編集・削除。任意でリマインド時刻を保持（実配信はしない）。
2. **日次チェックイン** — 指定日付でその日が対象の習慣のみ表示。完了／未完了を記録、過去日の
   遡り記録・修正も可能。当日ダッシュボードでリマインド時刻超過の未完了をハイライト。
3. **ストリーク・達成率の算出と可視化** — 現在／最長ストリーク（対象外の日は連続を途切れさせない）、
   週次・月次の達成率、カレンダーヒートマップを表示。

## MVP の範囲

- **含む**: コアユースケース（登録→チェックイン→可視化）と、その単体テスト／結合テスト。
- **含まない（後続マイルストーンへ）**:
  - リマインド通知の実配信（メール／ブラウザプッシュ等のスケジューリング基盤）
  - 認証・マルチユーザー対応
  - 目標連携、AI による習慣提案
  - モバイルアプリ／オフライン対応

## 制約・前提

- **リポジトリ構成**: 3つの独立した Git リポジトリ（`docs/`＝ドキュメント＆Claude設定、
  `backend/`＝API、`frontend/`＝UI）。正本は `docs/3_detail-design/repository-structure.md`。
- **技術スタック**: 壁打ちで確定（詳細は `docs/0_ideas/tech-stack.md`）。要点:
  - backend: **Go**（chi + sqlc + pgx）／DB: **PostgreSQL**（golang-migrate）
  - frontend: **Next.js**（React + TS、UIレンダリング専念）+ TanStack Query + Tailwind + shadcn/ui
  - API: **REST + OpenAPI 契約駆動**（`openapi.yaml` から Go/TS の型を生成）。Next は BFF にせずクライアントから直接 Go API を叩く
  - テスト: Go単体(testify)／Go結合(testcontainers+本物PG)／FE単体(Vitest)／E2E(Playwright)
  - ローカル: Docker Compose は Postgres のみ、backend/frontend はネイティブ起動
- **未確定の論点**:
  - タイムゾーン・日付境界の扱い、「特定曜日」ルールでのストリーク継続仕様の詳細（詳細設計で確定）
  - リマインド時刻超過ハイライトの判定基準（当日のみ／サーバー時刻基準）（詳細設計で確定）
  - 認証／通知実配信を後続で追加する際のマイルストーン区切り
