# 要求内容

## 概要

日々の習慣を登録・チェックインし、ストリークと達成率で継続を可視化するフロント＋バックエンドの
Web アプリ「HabitOS」。本要求書は長期プロジェクトの第一マイルストーン（コア機能: 登録→チェック
イン→可視化）を定義する。

## 背景

- 本プロジェクトの主目的は、ウォーターフォール型の開発ワークフロー（要件定義→基本設計→詳細設計
  →テスト設計→実装→結合テスト）を一通り回すこと。HabitOS はその題材。
- 生産性・自己管理領域で、ドメインモデルが明確・非自明なロジック（繰り返しルール／ストリーク計算
  ／集計）を持ち、設計・テスト設計が映える。
- フロント↔バックの連携があり結合テストの題材になる。段階的に育てられ長期前提に合う。
- 開発者自身が日々使える実用性も兼ねる。

## 実装対象の機能

### 1. 習慣の管理（CRUD）
- 習慣を登録・編集・削除できる（名前、カテゴリ、繰り返しルール）。
- 繰り返しルールは「毎日」「週 N 回」「特定曜日」を指定できる。
- 各習慣に任意でリマインド時刻を設定できる（保持のみ。実配信は行わない）。

### 2. 日次チェックイン
- 日付を選ぶと、その日が対象の習慣のみがチェックイン対象として表示される。
- 各習慣を「完了／未完了」で記録できる。過去日への遡り記録・修正も可能。
- 当日ダッシュボードで、リマインド時刻を過ぎた未完了の習慣をハイライト表示する。

### 3. ストリーク・達成率の算出と可視化
- 習慣ごとに現在ストリーク・最長ストリークを算出する（繰り返しルールに従い、対象外の日は連続を
  途切れさせない）。
- 週次・月次の達成率（対象日に対する完了日の割合）を算出する。
- ダッシュボードで達成率とカレンダーヒートマップを表示する。

## 受け入れ条件

### 習慣の管理（CRUD）
- [ ] 毎日／週 N 回／特定曜日の繰り返しで習慣を登録でき、一覧に反映される
- [ ] 習慣の編集・削除が一覧とチェックイン対象に正しく反映される
- [ ] 習慣ごとにリマインド時刻を設定・保持できる

### 日次チェックイン
- [ ] 指定日付で、その日が対象の習慣のみがチェックイン対象として表示される（週 N 回・特定曜日
      ルールでも正しい）
- [ ] 完了／未完了を記録でき、過去日の記録・修正が反映される
- [ ] 当日ダッシュボードでリマインド時刻超過の未完了習慣がハイライトされる

### ストリーク・達成率の算出と可視化
- [ ] チェックイン記録に応じて現在ストリーク・最長ストリークが正しく再計算される
- [ ] ストリーク計算のエッジケース（対象外の日を挟んでも連続とみなす／未完了で途切れる）が仕様どおり
- [ ] 週次・月次の達成率とカレンダーヒートマップが表示される

### 全体（結合）
- [ ] ドメインロジック（繰り返し判定・ストリーク・集計）の単体テストがグリーン
- [ ] フロント↔API の結合テストでコアユースケース（登録→チェックイン→可視化）が通る

## 成功指標

- ワークフロー（要件定義→基本設計→詳細設計→テスト設計→実装→結合テスト）を欠落なく最後まで
  回せた
- コアユースケース（登録→チェックイン→可視化）が結合テストで通る
- ドメインロジック（ストリーク／繰り返し／集計）に十分なテストカバレッジがある

## スコープ外

以下は第一マイルストーンでは実装しません（後続マイルストーンへ）:

- リマインド通知の実配信（メール／ブラウザプッシュ等のスケジューリング基盤）
- 認証・マルチユーザー対応（第一マイルストーンは単一ユーザー前提）
- 目標連携、AI による習慣提案
- モバイルアプリ／オフライン対応

## 未決事項

（設計フェーズで判断・確認する）

- 技術スタック（フロント／バック／DB）— architecture.md（/setup-project）で決定
- タイムゾーン・日付境界の扱い、および「特定曜日」ルールでのストリーク継続仕様の詳細 — 詳細設計で確定
- リマインド時刻超過ハイライトの判定基準（当日のみ／サーバー時刻基準）— 詳細設計で確定
- 認証／通知実配信を後続で追加する際のマイルストーン区切り
