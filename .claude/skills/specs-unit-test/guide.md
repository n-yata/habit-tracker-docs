# 単体テスト仕様書 作成ガイド

## 必須の網羅観点
- 正常系（代表的な入力の組み合わせ）
- 境界値（最小/最大、0件、範囲の端）
- 異常系（バリデーション違反、存在しないリソース、権限外等）

## 禁止事項（プロジェクトCLAUDE.md準拠）
- 「正しく動作すること」のような曖昧な期待結果
- テストを通すためだけの特別な条件分岐を実装側に持ち込む前提のケース
- 実DBが必要なケースをこのファイルに書くこと（`specs-integration-test` 側に回す）

## 品質チェックリスト

### test-api-{ID}-{slug}.md
- [ ] `docs/specs/3_detail-design/api/` の全APIに対応するファイルがあるか
- [ ] 各テストケースが具体的な入力値・期待結果で書かれているか
- [ ] 正常系・境界値・異常系がすべて含まれているか
- [ ] 「完了」チェック欄がすべての行にあるか
- [ ] テスト対象表に「統合テスト」の記載がないか（実DB不要なもののみ）
- [ ] 実DBが必要なケースは対応する `5_integration-test/` の画面ファイルへ回されているか
- [ ] 中核ロジック（Domain層等）のテストケースが重複せず、参照元に一本化されているか

### test-screen-{ID}-{slug}.md
- [ ] `docs/specs/3_detail-design/screen/` の全画面に対応するファイルがあるか
- [ ] コンポーネント単位でテストケースが分割されているか
- [ ] モック化する依存（API呼び出し等）が明記されているか
