# 結合テスト仕様書 作成ガイド

## 必須の網羅観点
- 画面の主要な操作フロー（登録→一覧反映、記録→集計反映 等）が実DBを通しで正しく動くこと
- Repository層の実制約（UNIQUE・CHECK・外部キー・カスケード）
- 複数テーブルを跨ぐ整合性（例: 論理削除後も関連テーブルのレコードが残る）
- 存在しないリソース・DB接続不可等の異常系が実際に正しいステータスで返ること

## 禁止事項（プロジェクトCLAUDE.md準拠）
- 「正しく動作すること」のような曖昧な期待結果
- ユニットテストで既に検証済みのロジック分岐の重複記載（本書は実DB込みの動作確認に絞る）
- API単位でのファイル分割（画面単位を維持する）

## 品質チェックリスト

- [ ] baseline「画面設計」の画面一覧の全画面に対応するファイルがあるか
- [ ] ファイルがAPI単位ではなく画面単位で分割されているか
- [ ] テスト対象表に、画面が呼ぶ全APIとDBテーブルが列挙されているか
- [ ] 各テストケースが実DBの前提状態・具体的な入力値・期待結果で書かれているか
- [ ] Repository層の実制約（UNIQUE・CHECK・外部キー）を検証するケースが含まれているか
- [ ] ユニットテストで検証済みのロジックと重複していないか
- [ ] 「完了」チェック欄がすべての行にあるか
- [ ] 対応する `4_unit-test/` 側のファイルから本書への参照リンクが付いているか
